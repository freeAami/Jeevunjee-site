# Architecture — Jeevunjee scholarship site (source ref 3f4d1a4)

**1. Product, principals, protected resources.** A public scholarship website plus a trustee/student portal for a family trust in Sri Lanka (~15 students, 2–3 trustees). Principals: **anonymous visitor/applicant** (submits an application with ID photos, certificates, family-income details); **student** (Supabase Auth user linked to one `students` row via a one-time access code; may read only their own file and upload invoices/results); **trustee/admin** (Supabase Auth user whose email is in `admin_emails`; full read/write). Protected resources: applicants' and students' PII (national ID images, DOB, income, family situation), payment ledger, trustee notes, access codes, admin role, storage objects, the trust's Gmail sending reputation/quota, and the hosting/deploy pipeline.

**2. Comparable baseline.** Typical Supabase + static-SPA apps: anon key is public by design and security rests entirely on Postgres RLS, SECURITY DEFINER function hygiene, storage.objects policies and Auth settings.

**3. Stack and deployment.** React 19 + Vite 8 + TypeScript SPA (`src/`), static hosting on GitHub Pages (`.github/workflows/deploy.yml`) and Vercel (`vercel.json`); no custom server. Backend = Supabase (Postgres + PostgREST + Auth + Storage) defined in `supabase/schema.sql`; anon URL/key committed in `.env.production` (public by design). A Google Apps Script web app (`apps-script/Code.gs`, deployed "execute as owner, access: anyone") receives an email-notification copy of each application (and the full application, files included, when Supabase is not configured) and sends mail via the owner's Gmail. `supabase/setup.mjs` is an operator-run CLI using a Supabase Management API token. Offline: `npm run build`, `npx tsc -b`, `supabase/tests/run_security_tests.py` (64 RLS checks on local Postgres 16 with a Supabase shim) all run locally; node_modules present.

**4. Entry surfaces → sinks.**
- Anonymous: PostgREST RPC `public.submit_application(jsonb,jsonb)` (`supabase/schema.sql:283`) → `applications` row; Storage upload to bucket `applications` path `incoming/...` (policy `schema.sql:476`; client `src/lib/application.ts:182`); Supabase Auth `signUp` (`src/portal/api.ts:126`) → trigger `handle_new_user` (`schema.sql:232`); password-reset email (`api.ts:145`); direct PostgREST table/RPC calls with the anon key (any function executable by `anon`/`public`); Apps Script `doPost` (`apps-script/Code.gs:57`) → Sheet row, Drive files, `MailApp.sendEmail` to trustees and to the applicant-supplied email (`Code.gs:90,207,218`).
- Student (authenticated): RLS-filtered reads (`schema.sql:436-440`), document insert (`schema.sql:443`), storage insert/read under `files/students/<id>/` (`schema.sql:486-497`), RPCs callable by `authenticated`.
- Trustee: all tables via `is_admin()` policies (`schema.sql:421-429`), RPCs `enrol_application` (`:313`), `issue_access_code` (`:265`); portal UI renders applicant-controlled data (`src/portal/admin/Applications.tsx`, `StudentFile.tsx`) and opens signed storage URLs in a new tab (`StudentFile.tsx:307`).
- Client-only: hash router (`src/App.tsx:12`), localStorage drafts with PII (`src/lib/application.ts:85-107`), Supabase session in localStorage key `jvj-portal-auth` (`src/lib/supabase.ts:17`), preview/demo mode when unconfigured (`src/portal/demo.ts`).
- Supply chain: GitHub Actions deploy + keepalive workflows, npm lockfile, Vercel build, `setup.mjs` handling a privileged token.

**5. Trust boundaries and strongest controls.** Anon→DB: RLS enabled on every public table with no anon policies; SECURITY DEFINER RPCs with `set search_path = public` and internal `is_admin()` checks; `submit_application` validates name/contact/signature, size ≤200 kB, ≤30 files, path regex. Anon→Storage: insert-only into `applications/incoming/*`; bucket size/MIME limits (`schema.sql:~465`). Signup: trigger raises unless email is unclaimed in `admin_emails` or a valid unexpired access code is supplied. Student→others: `my_student_id()` in every student policy. Trustee browser: React escaping; no `dangerouslySetInnerHTML` found. Apps Script: honeypot, required fields, `cell_()` formula neutralisation, `esc_()` HTML escaping. Auth settings (email confirmation off, redirect allow-list, rate limits), Storage MIME enforcement, Vercel/GitHub Pages headers and Apps Script deployment access are deployment facts not fully visible in source.
